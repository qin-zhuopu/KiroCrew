# 词表门只能证明拼写，证明不了词义 —— 以及句末标点怎样跟着一个词混进译文

时间：2026-10-10 15:55
相关：ACP-2213（hi 天城文分片翻译）、`/home/jereh/scratch/acp2213/`

## 现象

一整套自检全绿，译文里却有两个真错，肉眼和门禁都看不见：

1. **同一个英文短语，在同一张卡片里被译成两个不同的天城文词。**
   `manifest.description` 写 `असली Kiro Crew चैट सेशन`，
   而隔壁 `manifest.highlight_1` 写 `असली सत्र`。
   两处英文都是 "real … sessions"。
2. **`deploy_log_failed` 末尾多了一个 danda `।`**，而英文 `The log stream could not be opened`
   根本没有句号。

两道门当时的输出（都绿）：

```
[hi] 2 shard(s), 42 key(s), plurals [one other], 0 finding(s), 4.8% identical to English
OK: hi is ready to merge.
  character coverage: OK (no native script invented)
  word list: 0/42 value(s) contain an out-of-vocab word (0.0%)
```

## 根因

### 1. 词表门的判定域是「码位」，不是「词义」

`check-vocab.py` 的 tokenizer 是 `[ऀ-ॿ]+`，它只问一件事：**这串码位在已批准语料里原样出现过吗**。
`सत्र`（satra，字面义「行/排」）在 hi.json 出现 **196 次**，而且 7 个短值的英文确实写着
"Sessions"（`pages.chatSidebar.sessions`、`pages.overview.usageTab.sessions` 等）——
所以它是**合法的、被批准过的、仓里真的在用的**拼写。词表门看不见错误，因为错误不在码位上。

错在**词义分层**。量了一下仓里两个词的分工：

| 词 | 出现 | 仓里用来指 |
| --- | --- | --- |
| `सत्र` | 191 值 | 会话作为**记录/计数**：用量统计页、"No sessions for this item"、"Current session" |
| `सेशन` | 96 值 | **可打开的活会话**：如 `codeReviewSage.reviewChat` 的多个值（"Open a follow-up session"、"फ़ॉलो-अप सेशन खोलें"） |

我这批的语境是聊天，而且同一张卡片的兄弟键已经写了 `सेशन`，所以该用 `सेशन`。
我的取词器按 tf-idf 排名，`सत्र` 排 #0、`सेशन` 排 #1，取 #0 就选错了——
**排名是频率的函数，语境不是频率的函数。**

### 2. 句末标点会作为「词的一部分」被搬进来

天城文的 danda `।` 前面**不带空格**，所以 `[ऀ-ॿ]+` 把 `सका।` 切成**一个 token**。
我从批准值里整段切片搬运时，切到的最后一个 token 自带 `।`，
于是英文没有句号的键也带上了句末标点。

仓里的约定不是风格偏好，是硬数据：英文**无**句号的短值里，
**6496 条不带 danda，只有 5 条带**；英文有句号的 1467 条全部带。
所以多出来的那个 `।` 是确定性的错，不是可选风格。

## 修法

1. **标点奇偶性对称检查**（`hi/build-hi.py`）。原先只有「英文有句号 → 译文必须以 `।` 结尾」，
   补上反向：英文没句号而译文以 `।` 结尾时，剥掉它并打印 `FIXED PUNCT`。
   剥掉而不是报错，因为被切到的那个词本身是对的，只有它继承来的标点不对。
   修完 42 键 danda 奇偶性 `[]`（零不匹配）。
2. **同卡术语一致性**：`W:session#1` 取代 `W:session#0`，并在 spec 里写下为什么故意不用排名最高的那个。
   判据不是「这个词合不合法」，是「同一张卡片的两个键有没有指同一个东西」。

## 怎么避免

- **词表门 0.0% 不是质量证明，是「没有发明拼写」的证明**，仅此而已。
  它结构上抓不到：选错同义词、词义分层用反、语序、性数一致。
  这批的 13.1% 基线（`python3 calibrate-vocab.py hi` 实测：值级 937/7174 = 13.1%，
  词级 1341/47305 = 2.8%）是给「假词」定的，对「真词用错地方」零敏感。
- **跨键自查必须按「同一英文短语」横向比**，不能逐键竖着看。
  逐键看，两条都完美；两条并排看，矛盾立刻显形。
  写个小脚本把 42 键的 EN/HI 并排打出来读一遍，成本一分钟，抓到的错门禁一条都没抓到。
- **搬运算法要连标点一起想**：任何「按空白切词再拼回」的做法，
  都会把粘连标点（`।`、`…`、`?`）当成词的一部分搬走。
  凡搬运，就重新核对**译文末尾标点是否与英文末尾标点同型**。
- **取词器排名不能盲信**：tf-idf 只保证不是虚词，不保证语境对口。
  用 #0 以外的排名要在 spec 里写理由（我做了），用 #0 也**要读一遍它出现的例句**。
