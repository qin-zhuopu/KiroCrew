# 判「翻没翻」的正则写错，把 343 条正确中文全判成英文

时间：2026-10-10 · 关联：ACP-2113 / ACP-2212 · 相关：
[非拉丁文种禁止转写](20261010-010657-non-latin-spelling-gate-false-acquittals.md)、
[派工提示里我写了一个没测出来的数字](20261010-013931-invented-number-in-dispatch-prompt.md)

## 现象

要判断 zh-CN 的 `apps.aiStudio.*` 里哪些值还没翻，我写了一句「值里没有 CJK 字符
就算没翻」。跑出来是 **343 个键一个 CJK 字符都没有**，我据此差点上报「zh 的 aiStudio
整棵子树全是英文原语」。同一段判据拿去判印地语，报的也是「一个天城文都没有」。

真实数据是：343/343 全都有中文（`fmt_bold = 加粗`、`newWorkspace.name_placeholder =
如：设备管理`、`freeze_done = 需求已冻结`）。用正确判据重跑，全库只剩 **2** 个值不含
CJK，而且两个都**本来就该是拉丁文**：

| 键 | 值 | 为什么不是漏翻 |
|---|---|---|
| `apps.aiStudio.demo_product_dev` | `git tag` | 命令名 |
| `apps.aiStudio.release_job_field_commit` | `commit` | git 术语 |

## 根因

**字符类写错了**：我要的是「一个 CJK 区间」，实际写出来的形式没有方括号，正则把它
当成**一段字面量**去匹配 —— 于是它对任何正常中文都返回「不匹配」，我的取反判据
`not CJK.search(v)` 对每一条都成立，正确译文被 100% 定罪。

这类错的可怕之处在于**方向**：判据坏掉的一侧恰好是我准备据此下结论的那一侧。
「全都没翻」和「全都翻好了」都能被一个坏判据稳定产出，而「全军覆没」这种极端结果
看起来像是**发现了大问题**，不像工具坏了，所以我第一反应是报告发现，而不是怀疑判据。

## 修法

1. **码位用代码构造，不要手打字形**：`re.compile("[" + "".join(f"{chr(a)}-{chr(b)}"
   for a, b in RANGES) + "]")`。手写非拉丁区间本身就容易错（本次），而 Edit 工具在
   含 CJK 区间字面的行上还**匹配不到 old_string**（报 "tried swapping \uXXXX escapes"），
   改都改不动
2. **判据先自检，再让它说话**。断言写在同一段代码里，跑不过就整个流程不出结果：

   ```python
   assert CJK.search("加粗") and CJK.search("如：设备管理")
   assert CJK.search("削除") and CJK.search("ワーク") and CJK.search("삭제")
   assert not CJK.search("Delete workspace") and not CJK.search("{{name}}")
   assert DEVANAGARI.search("बंद करें") and not DEVANAGARI.search("Close")
   ```

3. **结果太极端就先怀疑尺子**。343/343 全军覆没、0 例外，现实里几乎不存在；
   真有这种数，第一假设是判据坏，第二假设才是数据坏。改完判据剩 2 条，
   而且那 2 条一眼看得出差额是**该保留的**——这才像真实分布

## 怎么避免

- **任何「有没有 X」的判据，先拿一个已知含 X 的样例和一个已知不含 X 的样例过一遍**，
  两个断言都要写。只断言「含 X 的要命中」不够——上面那次错，含 X 的样例同样不命中，
  而如果我连这条都写了，错就在第一轮暴露
- 判「翻没翻」除了码位判据，还要有**对照组**：同命名空间里改前就上线的译文当基线
  （见 [质检门未标定](20261010-014540-uncalibrated-translation-gate.md)）。
  没有对照组时，「不合格率 52.9%」这种数既可能是译文烂，也可能是尺子烂
- 顺带一条同源教训：`551` 这个数在本轮被人当成「我报过的 zh-only 键数」来纠正我，
  而我把本项目 34 个会话 transcript 全扫了一遍，assistant 侧一次都没出现过 551；
  含 551 的只有 `@2551`（消息里的 token id）和 `5476`（前端写死的端口常数）。
  **一个数在几个不同分母间串行**（`5 violation(s)`、343−288=55、30 孤儿键、68/74）
  比凭空编数更难查——它每个候选都是真测出来的，只是不是那个问题。
  所以引用自己的旧数字时，**连分母和量法一起引**，别只引数
