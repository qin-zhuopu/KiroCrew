# `--amend -F msg --only <file>` 改的是「上一笔提交」，而且一声不响

时间：2026-10-10 19:10 前后
后果：把已经写好的两笔提交（i18n 翻译 + 填坑笔记）**搅成一笔错的**，另一笔消失

## 现象

我以为自己在做这件事：

> 「给刚才那笔 hi 翻译提交补一个键，顺手把提交信息里的 14 改成 13」

跑的是：

```bash
git commit --amend -F commitmsg2.txt --only website/src/i18n/locales/hi.json
```

跑完 `git log` 一看：

```
c2c6b69f5e fix(i18n): translate the 181 AI Studio keys Hindi is missing   <- 笔记提交被改了标题
b3c46bd606 fix(i18n): translate the 181 AI Studio keys Hindi is missing   <- 真正的 hi 提交
```

`git show --stat HEAD` 显示 `c2c6b69f5e` 里装着**十篇笔记 + 一行 hi.json**，
提交信息却是 i18n 那段。查提交信息里有没有 `Co-Authored-By` 那行，
`git show` 的输出甚至被我拼成了乱码行 —— 总之：**改错了对象，而且它 exit 0、零警告**。

## 根因

**`--amend` 的宾语永远是 HEAD，不是我口中所指的那笔提交。** 我脑子里的对象是
「那笔 hi 翻译」（`b3c46bd606`），但在那之后我又提交了一笔笔记（`82cc31aaba`），
HEAD 已经前移。git 忠实地按字面执行：把 **HEAD（笔记提交）** 重写，
用我给的 i18n 提交信息替换它的信息，再把 `--only` 指定的那一行**追加**进它的内容。

于是同时发生三件事：

1. 笔记提交的**提交信息被替换**成 i18n 的（原始信息丢失，reflog 里才找得回）
2. 笔记提交的内容**多出一行 hi.json**（它的 stat 从 10 个文件变 11 个）
3. 那行 hi.json **本该进的那笔提交里没有它** —— 我这次收尾要补的第 13 个键根本没落进 i18n 提交

`--only` 让整件事更像「我在改那笔翻译提交」：它精确控制了内容来源，
我就误以为它同样控制了「改哪一笔」。**它不控制。目标只有一个来源：HEAD。**

## 修法

`git reset --mixed HEAD~2` 退回两笔（内容全留工作区，一行没丢），然后**先提交 hi.json，
再提交笔记**，两笔各用各的信息文件。因为**没有 push**，重写历史是安全的；
如果已经 push 过，就只能追加一笔修正，不能 reset。

## 怎么避免

- **`--amend` 之前必须先看一眼 HEAD 是不是我要改的那笔**：
  `git log --oneline -1`（或 `--format='%h %s'`）打出来对一下，
  一秒钟的成本，比事后重建两笔提交便宜得多
- **凡是「先提交 A、再提交 B、然后想回去补 A」的场合，`--amend` 一律是错的**，
  因为它只能碰 B。要么当时就补完 A 再提 B，要么另起一笔 fixup，
  要么明确接受「A 的补充进 B」这件事在语义上就是错的
- **`--only <路径>` 只约束内容，不约束目标**（`--amend` 家族同理，
  `--fixup`/`squash!` 才带目标语义）
- **收尾阶段尤其危险**：这时候往往会连着提好几笔（代码一笔、文档一笔），
  再回头补前面那笔的概率最高，而收尾时最容易省掉「先看 HEAD」这一步
- **改完必须 `git show --stat HEAD` 核对文件清单和提交信息**，
  不要只看 exit code —— 这次它就是 exit 0 地把错的送进去了
