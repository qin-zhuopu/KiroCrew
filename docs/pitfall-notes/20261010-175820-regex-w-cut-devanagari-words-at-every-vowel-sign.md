# `\w` 把天城文/孟加拉文的词在每个元音符号处切断，我的拼写闸因此报了个假的「0 可疑」

时间：2026-10-10 17:58
相关：ACP-2113（补非拉丁语种翻译）、`docs/pitfall-notes/20261010-174016-*`（拉丁同形字过全部
非拉丁门，同一批的另一半：那篇讲「形近码位不同的坏词没人看得见」，这篇讲**我为它造的这道闸
自己是怎么假绿的**）

## 现象

补 bn（孟加拉语）的 13 个键时，我造了一道拼写闸：新值里的每个词形，必须在**同语种目录的其余
部分**出现过；如果目录里没有、但和某个高频词只差一个字母，就判为「照屏幕重打字打坏了」。

我先要证明这道闸看得见坏词，就用程序化替换造了污染样本（`য` U+09AF → `য়` U+09DF，
即废弃的 nukta 变体；再把一个元音符号 `া` → `ি`），断言 `bad != good` 通过——
**文件里确实是两个不同的字符串**。

然后送进闸门：

```
可疑（目录 0 命中且有近邻高频形）0 / 新词形 0
```

0 可疑。样本没坏，闸也没响。看起来像「污染无效」，也像「我的闸是摆设」。

## 根因

切词用的 `re.compile(r"[^\W\d_]+", re.UNICODE)`。

Python 的 `\w`（在 `re.UNICODE` 下）**只收 `str.isalnum()` 为真的字符**。天城文/孟加拉文的
**元音符号（matra，如 `া ি ে ো`）是 `Mn`（组合记号），`isalnum()` 返回 False**。于是：

```
পরীক্ষা  →  用 \w 切 →  ['পর', 'ক্', 'ক্']     ← 每个元音符号处断一刀
পরীক্ষা  →  正确切法 →  ['পরীক্ষা']
```

词表侧和待查侧**被同样的方式切碎**，碎片彼此都能对上，编辑距离永远不相近，
「目录 0 命中 + 近邻高频」这个判据**结构上不可能触发**。

修好之后再看词表规模：`2899 形` → `7624 形`，**差 2.6 倍**。这一个数字就足够定位到切词坏了，
我当时只打印了「可疑数」，没打印「词表数」。

## 修法

按 Unicode 类别自己切，字母 `L*` 和组合记号 `M*` 都算词内字符：

```python
def words(text):
    out, cur = [], []
    for ch in text:
        if unicodedata.category(ch)[0] in ("L", "M"):
            cur.append(ch)
        elif cur:
            out.append("".join(cur))
            cur = []
    if cur:
        out.append("".join(cur))
    return out
```

修完同一份污染样本立刻响：

```
'পরীক্ষি'  近邻: পরীক্ষা×112
'করির'     近邻: করার×211，করি×5，কপির×4
```

同一份**未污染的**真分片仍是 0 可疑——这才叫过了闸。

## 怎么避免

- **给非拉丁语种造任何「按词」的判据之前，先把切词函数打印两行真实输出给我自己看**。
  `print(words('পরীক্ষা ঠিক করার'))` 一眼就能看出切错了。我跳过了这一步，
  于是先怀疑数据（「样本没污染成功」）再怀疑工具，白花一轮
- **别用 `\w` / `isalnum()` 判断「这是不是一个字母」**。`Mn`（组合记号）不是 alnum，
  但它是词的一部分。要按类别：`unicodedata.category(ch)[0] in "LM"`
- **词表规模本身就是一个指标，要打印出来**。「7624 形」和「2899 形」的差别比任何断言都响
- **自造污染样本要连「对照组」一起打印**：污染样本必须响、真分片必须不响，两行都在，
  `0 可疑` 才有意义。只看真分片那行，「闸没坏」和「闸是摆设」根本分不出来
  （同一课见 `20261010-174016-*` 里那条「自造污染样本差点是 no-op」）
