# 未提交的需求文件对开发副本彻底不存在，而它的报错长得像「合并冲突」

实战二号卡点（ACP-2227）。工作区 `/workspaces/sbjh`，2026-10-10 04:31~04:53。

## 现象

写需求助手把 `docs/需求图谱/施工设备借用单.json` / `.md` 写在**工作区主目录**里，
写完了没有提交（它的任务只是「把需求写出来」，不含提交）。

然后点〔开始开发〕。并行度 2，ACP-2207 的调度给每个并行节点从 `HEAD` 拉一棵
worktree（`.ai-studio/wt/1`）。于是：

1. 副本里**根本没有那两个需求文件** —— 未跟踪的文件不属于任何提交，
   `git worktree add` 检出的是提交，不是目录当前的样子。
2. 开发助手打开工作区看不见需求，只能照会话里那句话自己再想一版，在副本里
   **新建了同路径的文件**。
3. 它跑完、提交、合回主目录：节点 failed，看板写「合并冲突」，一个字的名
   字都没有。点〔从失败处继续〕，重试一次，照样失败，同样的四个字。

## 根因

两层，第二层才是坑。

**第一层：worktree 的基点是提交，不是目录。** 这条本身是设计（副本必须从干净的
HEAD 拉，否则会带上别人的现场），但没人想过「需求文件是助手刚写在磁盘上的、
从来没进过任何提交」这一档。所以主目录里最新鲜的需求，对副本是**零可见**。

**第二层（挖得最久的那个）：这种失败不是冲突，所以本模块原来那套「从 git 拿
冲突文件名」的机制彻底失灵。**

`worktree_merge` 原来在 merge 失败后跑：

```
git -c core.quotePath=false diff --name-only --diff-filter=U
```

这在**真冲突**（两边都改了同一行）现场是对的，实测有效。但「主目录有一个未跟踪
文件、而分支新建了同路径文件」时，git **连合并都不开始**就退了 —— 没有进入
conflicted 状态，index 里没有 unmerged 条目，所以这条命令**回空**。于是
`_merge_node` 里那句 `"、".join(exc.conflict_files) or str(exc)` 落到 `or` 那
一支，把 git 的**原文尾巴**当文件名贴上看板，而那句原文：

- 按 `LC_MESSAGES` 换语言（本机 `zh_CN.utf8`，回的是「未跟踪的工作区文件将被合
  并覆盖」，英文机器上是另一句）；
- 经过 `_git_failure` 只保留最后 5 行，git 列文件名的那几行经常正好被砍掉；
- 而且它只说「会被覆盖」，不说「那你先提交啊」。

结果就是看板上四个节点各挂一句谁也没法照着做的坏消息，而真正的现场（主目录里那
个未跟踪文件）在任何一处都看不见 —— **最像 bug 的地方是报错本身**。

## 修法

`backend/devdag.py` 三处，都在这一单里：

1. **开工前做一次「需求快照提交」**（`snapshot_requirements`）。`start` /
   从失败处继续 / `fix` 三处入口，在写状态文件之后、起循环之前跑：
   `git add -- docs/需求图谱` → `git diff --cached --name-only -- <同一目录>`
   （空就什么都不做）→ `git commit -m "docs(需求图谱): 开发前快照" -- <同一目录>`。
   三条**全部带路径限制**，绝不能 `add -A`：主目录里同时躺着开发助手的半截代码，
   把它们打进一条叫「需求快照」的提交，等于平台替人做一次他从没见过的提交。
   不加 `--no-verify`：钩子拒了就是坏了，绕过去只是让下一个人在自己机器上撞同
   一堵墙。提交失败 → 整轮 `failed`，message「需求快照提交失败：<原文>」，
   **一个副本都不建**（起了副本就是让四个助手在四个目录里各自重想一遍同一页）。
2. **副本一律从快照之后的 HEAD 拉**。不用改拉副本的代码：快照先落盘，
   `node["startCommit"]` 之后才取，基点自然是新的那一个提交。
3. **失败之后自己算交集**（`_untracked_blockers`），不再指望 git 那句话：
   主目录未跟踪名单（`ls-files --others --exclude-standard`）∩
   分支相对 `merge-base` 改动的文件名单（`diff --name-only <base> <branch>`），
   两个都是纯数据命令 + `core.quotePath=false`。算出来就把文件名和「先提交再重试」
   写进 `GitOpError.advice`，`_merge_node` 里 advice 优先于「合并冲突：<文件>」。

## 怎么避免

- **判断「git 有没有把仓库弄成冲突态」不要看它的措辞，也不要只看
  `--diff-filter=U` 非空**：后者只在真的进入 conflicted 状态时才有货。合并失败
  是一大类（未跟踪文件挡路、工作区脏、分支根本不存在、index.lock…），冲突只是其
  中一种。想知道是哪一种，就用**只读的数据命令自己算**（`ls-files --others`、
  `diff --name-only`、`merge-base`），别去 parse 它说什么 —— 那句话换语言就变。
- **任何「从 ACP 副本里能不能看见 X」的问题，先问 X 进过提交没有。** 未跟踪文件
  对 worktree、对 `git stash`、对 `git clean -fdx`、对下一个节点的会话，全都是
  不存在的。写文件的助手不提交，就等于没写。
- **给一个「跑在事件循环里、中途要起子进程」的状态机加闸门，先问它有没有孤儿判定。**
  这一条是我这次改动**自己带进来的**坑，不是原 bug：为了不让第二次点击挤进来，我在
  「写 `runState=running`」和「`create_task` 起循环」之间插了一次快照（子进程，几秒到
  几十秒）。而 `get()` 的孤儿判据正好是「文件说 running，可本进程没有循环」——看板每
  3 秒轮询 `GET dev/dag`，轮询只要落进这段窗口，就把这一轮判成「网关重启，中断」**并写
  回文件**，循环随后读到的是自己刚被判的死讯，于是一个节点都不派。改动前这段窗口只有
  几微秒（写盘到 create_task 之间没有 await），所以缺陷一直潜伏；**是快照把它从理论变
  成现实的**。教训：把一段同步代码换成子进程，等于把某个原本「理论上有、实际碰不到」
  的并发窗口放大几万倍，改完必须回头查这个模块有没有基于「状态 vs 内存态」差值的判定。
  修法是加一个 `async with self._latch()` 覆盖整段窗口（`_loop_alive` 认 `_starting`），
  且**用上下文管理器而不是手写 True/False**——抛异常时也要清标志，忘清一次的后果是
  孤儿判定永久失效（`get` 永远不再改判），那是「永远不红」的坏法，比报错更难发现。
  反面证据要跑出来才算数：我临时撤掉 `_loop_alive` 里认 `_starting` 那两行，
  `test_a_dashboard_poll_during_the_snapshot_does_not_abort_the_round` 立刻红在
  `assert 'failed' == 'running'`，正是这个缺陷的样子。
- 写这条的时候顺手记一句：**测试替身会把它自己的真函数测试吃掉**。本文件那条
  autouse 的 `no_real_snapshot` 把 `devdag.snapshot_requirements` 换成替身，
  而唯一那条想用**真 git** 验路径限制定的用例如果在测试体里读
  `devdag.snapshot_requirements`，拿到的是替身 —— 它会绿，而且绿得毫无意义。
  要真函数就在**模块导入时**抓一份引用（`_REAL_SNAPSHOT`）。
