# 产品原型智能演示设计方法论（AI Studio 适配版）

一句话总纲：**好的演示不是模拟用户点击页面，而是重放一个业务事件驱动的状态机——用可回放的状态快照，让用户看到系统"为什么"这样变化。**

（源头方法论沉淀自 Agent 工作负载页 / AI Coding 平台 / 文档版本 Diff / 图谱变更等 Demo；本文件是其面向 KiroCrew AI Studio 文档工作台的适配与落地规范。落地实现见
[`website/src/apps/ai-studio/demo/`](../../website/src/apps/ai-studio/demo/scenario.md)。）

## 一、演示的目标是"业务闭环"，不是页面跳转

每一段演示必须回答四问：为什么发生变化？谁触发的？系统内部发生了什么？结果是什么？

AI Studio 的标准闭环（本应用的主业务链，演示必须演它）：

```
用户编辑 requirements.md
  → 首次变更立即自动保存落一条草稿记录（diff 亮必有记录，无空窗）；后续输入停手 2s 再落
  → diff 图标由灰变亮（有未提交修改）
  → 用户点 diff，看到 红删绿增
  → 用户点提交
  → 旧内容进版本快照(vN)、修改历史清空、diff 图标回灰
```

反例（禁止）："点图标 → 弹层出现 → 关闭"——这是 UI 动画，不是业务。

## 二、先设计状态机，再写演示脚本

对象与状态：

- **文档**：`干净` → `草稿(有未提交修改, 含 N 条自动保存记录；N≥1——首次变更立即落记录)` → `已提交(vN)`
- **diff 图标**：`灰`（当前内容==最近提交）/ `亮`
- **修改历史图标**：`灰`（上次提交以来 0 条）/ `有 N 条`（提交后清零）
- **版本历史**：`v1..vN`，每版携带"vs 上一版"的 diff；v1 无前驱，整篇按新增

迁移规则（脚本的每个 action 必须落在规则内）：

```
干净 --编辑(首次变更立即落记录)--> 草稿(+1条记录；此后输入停手2s防抖再落，内容与上条相同则不落新条)
草稿 --提交--> 已提交(vN+1；快照进 versions/，草稿记录清空)
草稿 --恢复某条自动保存--> 草稿(当前内容=该条)
已提交 --编辑--> 草稿
```

页面只是状态的展示；脚本先改状态机，再对页面。

## 三、演示步骤 = 业务事件，不是按钮动作

每个 Step 的统一结构（事件 + 状态迁移 + UI 反馈 三件套）：

```json
{
  "id": "s2",
  "title": "编辑需求文档后，自动保存生效",
  "branch": null,
  "fixture": "main-004",
  "before": { "doc": "requirements.md", "diffIcon": "gray", "draftRecords": 0 },
  "action": { "event": "用户追加一行验收标准，首次变更立即落一条草稿记录" },
  "after":  { "diffIcon": "active", "draftRecords": 1 },
  "highlight": { "target": "[data-testid=doc-requirements.md]", "hint": "图标亮起：存在未提交的自动保存", "open": [] }
}
```

## 四、演示必须有"视觉引导层"

- 每步给 **高亮目标**（selector + 描边）与 **当前提示文案**（"当前：请查看 diff 图标的红绿行"）
- 引导层是**独立的 overlay 组件**（高亮框、提示条、上一步/下一步/自动播放的步进器），演示模式由 URL 参数 `?demo=<剧本名>` 注入——**业务组件内不许出现任何"为了演示"的代码**
- 弹层/菜单的展开也是引导层的事：脚本说"现在该看修改历史面板"，引导层负责把它打开并指过去（`highlight.open` 的 selector 序列按序程序化点击）

## 五、演示不改真实数据：状态快照，可回放

- 每个 Step 携带一份完整状态快照（`fixtures/state-*.json`），对应后端 store 的一份数据（演示模式下把数据层指向快照 fake，fetch 一个都不发）
- 下一步 = 加载 State(n+1)；上一步 = 加载 State(n-1)；**禁止反向计算/反向操作恢复**
- 演示全程写独立 home（`KIROCREW_HOME` 指 demo 目录），**绝不碰用户/演示环境的真实项目数据**

## 六、状态层与展示层分离（回放稳定性的根）

- **状态层**：现在有哪些文档/草稿/版本、内容是什么——快照驱动
- **展示层**：现在高亮什么、提示什么、该开哪个面板——剧本驱动
- 禁止 `step 执行 → 改数据 → setTimeout 开弹窗` 的耦合写法（回退残留、自动播放冲突、CDP 不稳三坑都源于它）
- 回退 = 状态层整体换快照 + 展示层按该步剧本重放，两者各自幂等（实现上：每一步都整体换装——数据层载入快照、工作台按步号重挂载、引导层重放该步的 `open` 序列——重复进入同一步必然得到同一画面）

## 七、必须覆盖异常分支，不止 happy path

AI Studio 至少要演：

- 无修改时 diff 图标置灰不可点（为什么灰 → 状态机里"当前==最近提交"）
- 修改历史为空（刚提交完）——顺便讲"提交即清空"的规则
- 最早版本无上一版 → diff 整篇为新增
- 从一条自动保存记录**恢复**的分支（草稿态回到过去）

分支步骤与主线共用同一套 Step 结构，剧本里标 `branch: "alt-N"`。

## 八、剧本测试测的是剧本，不是页面

剧本测试（`website/src/apps/ai-studio/demo/demoScript.test.tsx`）必须验证四件事（"按钮存在/文字存在"级别的测试不算数）：

1. **状态迁移**：执行 step 后 before/after 声明的状态逐项为真（DOM data 属性或 store 断言）
2. **引导落位**：当前步的 highlight selector 命中且可见
3. **回放一致**：手动"下一步"×N 的最终状态 == 自动播放到第 N 步的状态
4. **回退恢复**：走到 step5 → 上一步 → 页面与快照 State4 完全一致（最容易出 bug 的一处）

测试跑在演示模式 + 独立数据 fake 上；CDP 调用一律带 timeout 与总闸。

## 九、标准目录结构（本仓库的实际落地）

```
website/src/apps/ai-studio/demo/
  scenario.md                # 业务故事线（人读的剧本说明书）
  steps/*.json               # 步骤剧本（三件套结构，三条线）
  fixtures/*.json            # 每步状态快照（generate_fixtures.py 生成，保证与后端 difflib 语义一致）
  generate_fixtures.py       # 快照与剧本的生成器（改动文档内容后重跑）
  types.ts                   # Step / 状态快照的 schema
  runtime.ts                 # 演示运行时：?demo= 解析、快照 fake 数据层、步进状态
  overlay.tsx                # 视觉引导层（高亮框/提示条/上一步/下一步/自动播放）
  demoScript.test.tsx        # 剧本测试（上面四项断言）
docs/guides/ai-studio-demo-methodology.md   # 本方法论（登记进 docs/README.md 索引）
```

## 十、示范剧本（本仓库的三条线）

- **主线 `?demo=main-membership-points`「会员积分系统」**：进项目 → 版本历史看 v1 整篇新增、v2 增量 diff（含"返回编辑"）→ 回编辑器改两行 → 首次变更立即自动保存落记录 → diff 图标亮起 → 打开红绿 diff → 提交 → 修改历史清空、版本历史 +1、图标回灰
- **分支 A `?demo=alt-1-draft-restore`「App 官网改版」**：有未提交草稿 → 打开修改历史列表 → 挑较早一条看 diff 并**恢复**（草稿态回到过去）→ 恢复后的文本再被防抖记为新一条
- **分支 B `?demo=alt-2-empty-gray`「空项目示例」**：三个图标全灰态，逐步解释"为什么是灰的"（diff 灰 = 当前==最近提交；修改历史灰 = 提交后清空；版本历史灰 = 从未提交）

## 怎么打开演示

1. 用**独立 home** 起网关（演示环境隔离，不碰真实数据）：

   ```bash
   KIROCREW_HOME=/tmp/kiro-demo-home python3 -m kiro_crew gateway   # 按需换端口
   ```

2. 往网关里灌演示项目数据（或直接复用 `fixtures/*.json` 里的 `project`/`docs` 经 API 创建）。
3. 浏览器打开 `#/ai-studio/projects/<项目id>?demo=main-membership-points`（剧本名对应 `steps/<剧本名>.json`）。命中演示模式时：数据层由快照 fake 接管（不发任何 fetch、写操作只动内存），右下角出现步进器；未带 `?demo=` 时页面行为与平时完全一致。
